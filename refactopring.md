В метода OnInit, регистрируются MutationObserver/ResizeObserver/IntersectionObserver

## РЕАЛИЗОВАНО ✓

### MutationObserver
Наблюдает за элементом с классом .virtual-scroll-content. Задача данного MutationObserver - реагировать на добавление новых узлов, добавлять в кеш их размеры и первоначальный offset, следить за именением параметра data-index. При изменении параметра data-index необходимо проверить наличие данных по новому индексу и в случае его отсутствия добавить данные в кеш. Так же зарегистрировать элемент в ResizeObserver и IntersectionObserver.

**Реализация:** 
- При добавлении новых узлов: кеширует начальный размер через `cacheElementMeasurement()`, регистрирует в ResizeObserver и IntersectionObserver
- При изменении data-index: проверяет наличие данных в кеше, добавляет при отсутствии, обеспечивает регистрацию в обоих observers

### ResizeObserver
Наблюдает за изменением размера существующего элемента. При изменении размера проверить индекс элемента изменившего свой размер, проверить присутствует ли в кеше данные, при их отсутствии создать обьект с размерами и offset, сохранить данные в кеше. Так же ResizeObserver отслеживает изменение размера элемента с классом .virtual-scroll-content. На основе данных изменений принимается решение об удалении или добавлении новых элементов в пул.

**Реализация:**
- Координируется с MutationObserver: MutationObserver кеширует начальный размер, ResizeObserver отслеживает последующие изменения
- Обрабатывает динамическое изменение контента и обновляет кеш
- Отслеживает изменения .virtual-scroll-content для управления пулом

### IntersectionObserver
Отслеживает, когда элемент появляется или исчезает из поля зрения viewport. При обнаружении данных изменений принимается решение об изменении данных в элементе пула.

**Реализация:**
- Наблюдает за пересечением элементов с viewport
- При входе элемента в viewport: кеширует измерения если отсутствуют
- При выходе элемента из viewport: определяет возможность рециклинга
- Использует rootMargin="100px" для предзагрузки элементов
- Работает совместно со scroll listener для оптимальной производительности

### Решения по архитектуре:

**Q: Позволяет ли IntersectionObserver избавится от слушателя скролла?**
A: НЕТ - оба используются вместе:
- Scroll listener: точное отслеживание позиции и триггер пересчета для плавного скроллинга
- IntersectionObserver: оптимизация через отслеживание видимости и умное кеширование

**Q: Стоит ли отслеживать данное событие для всего компонента или нет?**
A: Отслеживаются отдельные элементы виртуального пула, с корневым элементом scroll container

### Добавленные методы:
- `observeElementIntersection(element)` - регистрация элемента в IntersectionObserver
- `cacheElementMeasurement(element, index)` - кеширование размера и offset элемента
- `getMinMaxPoolIndices()` - получение граничных индексов пула для логики рециклинга
- `setupIntersectionObserver()` - инициализация IntersectionObserver
